## 提交信息生成规则

### 语言要求

- 生成的提交信息**必须使用中文**。
- 禁止输出英文提交信息。

### 格式

`<类型>(<范围>): <描述>`

- 首行：类型 + 可选范围 + 冒号 + 空格 + 简短中文描述，**不超过 50 个字符**。
- 正文（可选）：首行后空一行，再用中文详细说明变更内容与原因。
- 脚注（可选）：正文后空一行，用于 `BREAKING CHANGE:` 或关联 issue。

### 允许的类型

- `feat`：新功能
- `fix`：修复 Bug
- `refactor`：重构（不改变功能逻辑）
- `docs`：文档更新
- `style`：代码格式调整（不影响功能）
- `perf`：性能优化
- `test`：测试相关
- `chore`：构建/工具/依赖变动
- `build`：构建系统或外部依赖变动
- `ci`：CI 配置或脚本变动
- `revert`：回退之前的提交

### 内容要求

- 说明**改了什么**以及**为什么改**。
- 避免模糊表述，如“更新”“修复 bug”“修改了一些东西”。
- 描述使用祈使语气（如“添加登录校验”，而非“添加了登录校验”）。
- 变更较简单时省略正文；仅在需要额外上下文时补充正文。

### 示例

feat(auth): 添加登录页短信验证码校验

在登录流程中增加短信验证码校验步骤，防止未授权访问。
